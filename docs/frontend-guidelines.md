# 前端设计与实现规范

本规范用于 SynthV 对话工作台的界面开发和评审。整体延续类似 Codex Desktop 的黑白、中性灰桌面工作台：突出会话内容，导航安静，工程工具清楚，操作层级稳定。本文是需要遵循的规则与检查表，不代表每个条目已通过自动化或人工验收。

## 技术与职责

工作台是随本地 Python 服务提供的静态页面，继续使用原生 HTML、CSS 和 JavaScript。不要为按钮、图标、主题或响应式布局引入前端框架、组件库、运行时 CDN 或新增打包构建链。可复用行为应集中在小型共享模块中，业务状态仍由对应页面负责。

| 文件 | 负责内容 |
|---|---|
| `web/index.html` | 页面语义、稳定 ID、静态表单和导航结构 |
| `web/style.css` | 主题令牌、共享控件、页面布局、容器查询与交互状态 |
| `web/ui.js` | 本地 SVG 图标、图标按钮创建与更新、静态图标初始化 |
| `web/curves.js` | 真实参数目录、手动曲线草稿、统一的宿主预览与表示方式说明 |
| `web/layout.js` | 系统/浅色/深色偏好、侧栏宽度及可访问的分隔条交互 |
| `web/app.js` | 共享请求和工程工具状态、手动调参、A/B 录音及设置入口 |
| `web/pages.js` | 中央页面切换、独立录音页、回收站 |
| `web/models.js` | 会话平台、模型、推理选项及目录刷新状态 |
| `web/chat.js` | 会话列表、消息、附件、提案和模型任务进度 |

公共 UI 模块不发请求、不保存业务数据、不决定写入许可。使用 `SynthVWorkbench` 等现有入口和 `synthv:*` 事件连接业务模块，避免复制状态、重复绑定同一按钮或根据按钮文字判断业务状态。主题脚本仍需尽早应用偏好；依赖 DOM 的脚本按依赖顺序初始化，`ui.js` 和 `curves.js` 应先于使用它们的业务脚本可用。

## 主题与层级

颜色从 `style.css` 的语义令牌取得，业务选择器不得另造固定绿、蓝、红色。暗色主题不能仅反转背景而保留浅色边框、表单或波形。Canvas 波形读取主题变量；原生表单和音频控件通过 `color-scheme` 配合主题。

| 用途 | 当前语义令牌 |
|---|---|
| 主背景、导航、面板 | `--bg`、`--sidebar`、`--panel`、`--panel-raised` |
| 交互背景 | `--surface-hover`、`--surface-selected`、`--input` |
| 正文与辅助文字 | `--text`、`--muted`、`--subtle` |
| 边框与重点操作 | `--border`、`--border-strong`、`--accent`、`--accent-strong`、`--on-accent` |
| 错误、波形与遮罩 | `--danger`、`--waveform-a`、`--waveform-b`、`--overlay` |

`--danger` 也是中性灰语义，不依靠颜色单独表达危险。错误使用明确文字、边框或图标，并保留能够继续处理的操作。选中、可写、忙碌、未配置等状态同时有文本或可访问状态说明。

默认跟随系统，系统变化即时生效；用户明确选择浅色或深色时优先使用个人偏好。刷新应保持偏好，存储被禁用或值损坏时回到可用默认值。浏览器存储仅保存必要的非秘密偏好或定位信息，不加入 API key、完整会话、录音或工程内容。模型目录缓存由本机后端保存，初始化、切换会话和切换平台只发本地 GET；不能为了补齐空目录、过期缓存或能力说明自动调用供应商。

## 尺寸与间距

新增和改造控件使用以下统一尺寸。遗留选择器的旧值不能作为新增例外依据；有必要的特殊结构应解释原因并单独验收。

| 项目 | 规范 |
|---|---|
| 普通单行按钮、输入框、下拉框 | 38 px 高；同一行采用相同 border-box 高度 |
| 紧凑控件 | 34 px 高，适用于工程工具和模型工具栏 |
| 纯图标按钮 | 桌面 34 × 34 px，图标居中，不因内容变窄 |
| 粗指针设备 | 使用 `pointer: coarse` 条件，将图标按钮及紧凑可点击控件的触控目标提升到至少 44 × 44 px，并重新检查换行 |
| SVG 图标 | 默认 18 × 18 px、描边 1.75；使用 `currentColor`，保持同一视觉重量 |
| 间距尺度 | 4 / 8 / 12 / 16 / 24 / 32 px；优先用 `gap` 表达同组间距 |
| 控件圆角 | 8 px |
| 卡片圆角 | 12 px；圆形状态点、开关等形状不强行改成卡片 |

字体沿用本地系统字体栈，不为外观加载远程字体。正文、辅助说明和控件保持清晰层级；不要靠无限缩小字体塞入更多内容。多行文本框按内容区域设计，不受单行 38 px 高度限制。

同一行的 label 高度不应改变控件底边对齐；使用 Grid/Flex 的对齐能力。紧凑区域覆盖共享尺寸令牌，不为每个按钮分别写宽高。不要通过提高选择器优先级、连续追加补丁或全局 `!important` 修复局部对齐问题。

## 按钮与图标

操作分三层，避免所有按钮都只有图标或都使用主色块：

| 类型 | 呈现与例子 |
|---|---|
| 主要操作 | 保留明确文字，如发送、保存设置、开始录制、预览修改、确认应用；可附辅助图标 |
| 管理工具 | 使用统一图标按钮，如刷新、重命名/备注、星标、删除、关闭、移除附件 |
| 页面导航 | 图标加文字，如会话、音频素材、录音、回收站、模型设置 |

危险操作可以用图标打开操作选择或确认区域，但最终确认保留“确认永久删除”等具体文字。图标化不能取消预览确认、删除方式选择、忙碌禁用或错误反馈。

图标只来自 `web/ui.js` 的本地白名单。不要混用 Emoji、Unicode 字形、远程图片和手写的另一套 SVG；它们在字体、主题与平台之间会有不同基线或粗细。SVG 本身是装饰内容，按钮的可访问名称由按钮提供。

共享 API 约定如下：

| API | 职责 |
|---|---|
| `SynthVUI.icon(name)` | 返回本地白名单图标的 SVG DOM 节点 |
| `SynthVUI.iconButton(name, label, { id, pressed, className } = {})` | 创建图标按钮；可选参数用于稳定 ID、切换状态及附加样式类 |
| `SynthVUI.setIconButton(button, name, label)` | 更新已有按钮的图标、`title` 与 `aria-label`，保留其他属性 |
| `SynthVUI.hydrate(root = document)` | 初始化 `root` 内带 `data-ui-icon` 的静态图标 |

调用时使用模块已定义的图标名；新增图标应先加入同一字典。刷新中、星标切换等动态更新应调用 `setIconButton`，不要用 `textContent = "…"` 覆盖整颗图标按钮。更新图标不会替代业务代码对 `disabled`、`aria-pressed`、`aria-expanded`、忙碌状态和事件监听的管理。

所有纯图标按钮同时具有简洁的 `title` 和 `aria-label`，例如“刷新素材列表”“移除音频附件”；切换状态时同步更新名称。原生 `title` 用于鼠标悬停提示，键盘与辅助技术依赖可访问名称，不能假设键盘聚焦时一定显示悬停提示。不新增可能遮挡输入区的自绘 tooltip。

## 焦点、禁用与可访问性

使用原生 `button`、`input`、`select` 等语义元素；非提交按钮明确 `type="button"`。保留统一 `:focus-visible` 轮廓，不以去掉焦点样式换取视觉整洁。复合输入区可以用容器焦点样式，但必须清楚显示当前键盘位置。

禁用状态使用原生 `disabled`，并保持可理解的外观和必要的原因说明。不能只调低透明度或设置 `pointer-events: none`，让键盘仍能提交操作。忙碌时保留可见阶段、等待时间和错误容器，完成或失败后恢复正确控件状态，不把旧错误藏在只有鼠标可见的提示中。

导航与标签页维护 `aria-current` 或 `aria-selected` 等对应状态；开关、星标和抽屉使用相应可访问状态。可拖分隔条保留 `role="separator"`、方向与范围信息，支持方向键、Home/End、双击复位；隐藏的侧栏与分隔条不能继续占据 Tab 顺序。Escape 关闭临时抽屉或取消拖动后，应把焦点放回有意义的位置。

异步反馈沿用页面中的状态/错误区域；不要每个流式字符都触发强制播报。用户输入、模型文本、文件名和错误内容通过 `textContent` 等安全 DOM 接口展示，不能拼入 `innerHTML`、SVG 路径、任意属性名或事件代码。

## 容器响应式与滚动

布局以可用容器宽度为依据，不能只根据浏览器总宽度估计中间区域。用户可以拖动两侧栏，因此宽桌面上的中央表单也可能很窄。

- 保留桌面导航、中央主页面、右侧工程工具的分工。隐藏侧栏时同时移除对应分隔列，不能留下空白占位。
- 中央页面和会话输入区域使用现有 `workspace`、`composer` 容器查询调整表单排列。Grid 使用 `minmax(0, 1fr)`，弹性子元素允许 `min-width: 0`。
- 模型平台、模型 ID、推理选项和刷新按钮不能互相覆盖；空间不足时按组换行，主要操作保持可见。
- 音频素材列表独立滚动，确认附件操作栏留在所属页面的布局中。不要用全窗口 `position: fixed` 把底栏压到其他面板上。
- 长文件名、模型 ID、备注、错误和消息正文不得撑宽页面。标题可截断并保留完整名称的访问方式；正文与错误优先折行，确需横向滚动时局限在内容容器内。
- 窄窗口使用现有抽屉行为。抽屉关闭后不阻挡中央页面，页面切换保留未发送草稿；表单与确认按钮可以单列排列，不得缩到不可点击。

390、1150、1440 px 是验收宽度，不是必须新增的断点。实际断点依据内容和既有布局确定；1150 px 需要特别检查双侧栏打开与调整宽度后的中央可用空间。

## 运行状态与模型内容

界面清理不能删去未配置、写入关闭、请求失败、版本冲突、过期预览或结果未知等真实状态。区分“已保存配置”和“已验证连接”，区分“模型回复”和“宿主已应用”。

等待时显示实际阶段和持续计时，不模拟完成百分比。圆环只表示任务进行中；减少动态效果时可以按现有策略降低运动，但文字状态和计时必须保留，不能让任务看起来已经停止。

发送消息时，在新建会话、保存模型选项和提交消息等异步步骤之前立即显示用户正文与本次附件的公开信息。临时发送快照只留在页面内存，明确区分准备发送、已入队、未发送与状态未确认；入队不能冒充已持久化。服务器正式记录返回后按所属会话与本次发送内容去重替换，旧的同文消息不能吞掉新发送。失败保留草稿，不自动重新请求模型，也不将临时消息串入其他会话。

供应商模型预设和从 API 读取的账号目录须明确区分。预设不证明账号已开通；不能仅因同属多模态系列就推断支持音频。Qwen 普通 Flash/Max 与 Omni 的输入能力、音频请求格式和推理档位由本地规则分别处理，附件不兼容时提示用户主动更换模型，不自动路由到另一模型。

可见思考摘要只显示服务返回的真实摘要；没有内容时明确说明，不生成占位思考或推断隐藏过程。正文流式片段不是可执行提案，只有完整响应通过后端校验后才生成正式提案。所有应用继续遵循实际预览和逐项确认；`unknown` 不能通过重新启用按钮绕过防重放。`applied` 只提供“撤销后重新预览”入口，由后端核对完整原状态并生成新预览；前端不能自行认定已撤销或恢复旧确认按钮。

## 参数目录与曲线展示

手动编辑和聊天提案共用 `web/curves.js`，通过 `SynthVCurves.createEditor()`、`createPreview()` 和 `representation()` 管理草稿与展示；请求、忙碌状态和确认仍由业务页面负责。不要在聊天与右侧工程工具分别实现另一套曲线数值含义或预览绘图。图形随主题和容器尺寸更新，保留文字单位、控制点输入及错误说明，不能仅凭线条颜色传达参数含义。

- 参数名称来自当前返回目录，声线模式必须使用其中的 `modeName`，不得硬编码某个声库一定提供 Cute、Sweet 等风格。目录可能只含当前已返回设置，页面应展示这一限制，不能把缺项擅自补成可用选项。
- 手动补充是独立的用户操作：先提示用户核对 SynthV 当前声库面板原名，再提交 `{name,selection}`。名称去首尾空白后最多 80 个 UTF-8 字节，不能把 HTML maxlength 字符数当成字节校验，也不能偷偷截断名称。请求携带最近读取的完整选区，由后端抽取身份字段；过期或注册失败时不在本地伪造成功选项。展示 `source=host` 与 `source=user` 的区别，说明补充仅在桥接会话中有效，并不代表 API 已枚举或验证全部声线。
- 先看 `capabilities.curves`、`capabilities.nativePitch` 和参数 `available`。脚本 API 实际不可用时禁用相关入口并解释原因，不能仅凭版本号、静态标签或官方文档推断可用；原生音高不可用不影响已支持的 pitchDelta 偏移入口。
- 草稿协议沿用增量或曲线二选一。曲线为 2～64 个 `[position,value]`，位置严格递增且首尾为 0、1；横轴是当前连续选区的时间比例。通用/声线/pitchDelta 的值为偏移，pitchCurve 为绝对 MIDI，必须显示对应单位。
- 默认 `smooth`，`points` 是显式的自动化控制点选项。原生 pitchCurve 只开放 smooth，并按真实音符 pitch 加 groupPitchOffset 计算允许音域；缺少可靠资料时禁用，不能猜测 60 或把音分当 MIDI 提交。
- 会话输入区的绘制模式是独立持久偏好，发送时固定快照，切换不会改写历史提案；控制点模式的音高提案使用 pitchDelta。AI 逐音符包络由本机编译，前端不拼造新的音符或曲线来绕过 64 点上限。
- 参数、控制点、表示方式或选区变化后清除旧确认入口，重新请求宿主预览。提案名称优先使用生成时的 label/unit/kind/modeName，不能切换声库后用新目录重新解释旧提案。
- 正式预览的曲线数值只取宿主返回的 `curvePreview`，最多 256 个 `{position,before,after}`。`pitchDelta` 可以按下述规则投影到音符上作为参考显示；投影和音符边界处的采样插值不能改写原始参数数据。before 缺失或为 null 时明确前值不可用，不补零、不用音符音高或浏览器插值冒充生成音高。草稿可视化必须与正式宿主预览区分。
- 音符矩形只来自预览返回的 `notes`，表示所选音符的时间与已经包含组移调的乐谱音高，不能再次叠加移调。所有参数的音符均按实际 MIDI 上下排列，禁止将非原生音高参数的音符压成同一水平线。钢琴卷帘提供左侧键盘、半音网格和音名参照，较高音高位于上方；音域较大时可减少文字标签，不能改变半音间距或音符坐标。
- 原生 `pitchCurve` 的候选线与音符共用绝对 MIDI 纵轴。`pitchDelta` 在绘制、控制点两种模式下也默认叠加在音符所在的钢琴卷帘中，显示位置为“乐谱 MIDI 音高 + 参数音分值 / 100”，明确标为参考叠加，不能称为实际合成音高或测得基频。宿主 before/after 为参数总值，分别投影，不能把它们误当成本次增量再加一次；音符已含移调，不能重复叠加。
- 音高偏移的参考连线按音符边界分段，在休止处断开，不跨相邻音符的不同音高画出假滑音。仅为显示边界而插值的点不能画成实际控制点。音符重叠或缺少有效音符时回退音分参数轨并说明原因。气声等非音高参数继续使用下方参数轨，保留各自单位，并与音符轨严格对齐时间；不得把 dB、百分点等直接当作 MIDI。
- `smooth` 与 `points` 的图示应区分曲线和节点。实际控制点仅从宿主预览的 `controlPoints` 绘制，不得给固定间隔的 `curvePreview` 采样加圆点冒充宿主节点。没有节点资料的旧预览仍显示已有曲线并说明节点未提供；缺少音符时不借用当前选区补齐历史快照。标签明确音符是乐谱参照，不是演唱基频；音符叠层不能补造缺失的 before 曲线。
- 手动 `pitchDelta` 草稿同样按音符叠加显示，指针纵坐标须先减去当前位置的乐谱音高，再换算为音分增量；提交协议、数值输入、增量上限保持音分含义。休止位置没有唯一的音符基线，不能凭空指定音高来接收手绘落点。
- 图形使用统一的坐标布局计算；手绘指针映射必须使用当前实际绘图区和对应单位，不能保留旧的固定高度、顶部间距或把 MIDI 值误写入音分参数。容器宽度、侧栏拖动、设备像素比和主题变化后重新绘制，不能只响应窗口大小变化。窄区域仍保留音高排列与各参数单位，不靠压平音符节省高度。
- 展示 `beforePointCount`、`pointCount`、`pointReduction` 和 `capabilityWarnings`。`pointReduction` 是减少的点数，不是百分比；representation 分别显示“精简自动化曲线”“密集自动化控制点”“原生音高曲线”。曲线图不是音频，也不代表已经应用。

## 规范落地检查表
