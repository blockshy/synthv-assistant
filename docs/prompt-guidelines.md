# 内置提示词规范

当前工作台只开放文字咨询与明确附带选区的参数规划，使用 `synthv_assistant/prompts.py` 按本次宿主能力构造提示。公共会话入口拒绝非空音频附件，传给规划器的音频列表为空；内部音频分支和听评模板保留用于历史兼容，不是当前可用功能。系统规则不包含密钥、工程路径、私有指纹或用户原文；当前要求、歌词和历史通过受限资料消息发送。增加新功能时，应同时核对实际解析器、工具契约和测试，避免只修改提示词而声称已经支持新动作。

## 任务与输出

| 功能 | 主要规则 | 输出 |
|---|---|---|
| 无选区咨询 | 回答当前问题，不虚构宿主读取或已执行操作 | 严格 `{text,actions}` JSON，`actions=[]` |
| 附带选区的调参 | 参考实际目录、现值与音符时间，默认保留已有音高；优先少量局部小幅修饰 | 最多五个不重复参数，按当前能力采用 `delta`、`curve`、`noteCurves` 或 `pitchShape` |
| 当前会话的证据边界 | 区分用户描述、乐谱、宿主计算音高与实际听感 | 不声称听过音频或取得录音基频 |
| MCP 客户端 | 使用各工具公开字段，先读取、预览，再由用户确认应用 | 工具调用与简短说明；不套用聊天 JSON 或内部 `noteCurves` 字段 |

纯咨询不携带局部曲线和原生音高的完整动作说明；缺少可靠音符时间时不引导模型猜测 `noteCurves`。控制点模式不生成原生音高；原生重绘仅作为用户明确要求的替换操作，并说明不能保留全部演唱细节。声线名称始终以本次目录为准。

## 证据、篇幅与执行

要求模型简洁说明判断依据和不确定性，不重复全部规则、参数采样或内部推理。简单咨询通常不超过 200 字，调参说明通常 200～600 字，单项理由通常 20～80 字。用户要求详细解释时可展开，但不得超出解析器硬限制：聊天 `text` 6,000 字符、单项 `reason` 1,000 字符、完整正文 24,000 字符。

调参位置按本次选区的音符与时间资料说明。没有测量依据时不编造精确 F0、LUFS 或质量分数；不能由参数数值推断已经听到的效果。现有采样不是完整曲线，宿主计算音高不是录音实测；缺失值不能补成零或默认值。

所有生成动作仍需本地结构、单位、能力与范围校验，并经过实际宿主预览和用户确认。提示词不能授予权限、解除边界或证明听感改善。模型响应遇到明确截断、过滤、工具调用或拒绝时不能作为完整方案；不自动重新调用付费接口。

公开思考摘要只展示供应商实际返回的内容，达到 12,000 字符后停止保留更多展示内容，继续接收最终答案。传输和最终正文采用独立预算，详见 [平台与流式请求](architecture.md#平台与流式请求)。

## 历史模板的保留范围

`prompts.py`、规划器与 `review.py` 仍包含单段、双段音频任务分支：单段只分析 A；双段先判断可比性，A/B 只代表附件顺序，不预设 B 更好；片段时间使用近似秒数，观察需考虑静音、伴奏与响度差异。旧听评模板的建议篇幅为 300～800 字。旧网页快捷提示也保留了显式选择附件的实现。这些内容用于解释和维护历史代码，不恢复录音、上传、听评或 MCP 音频工具，不应出现在当前工作台的操作指引中。历史流程详见 [音频评审归档](audio-review.md)。

## 验证

`tests/test_prompts.py` 检查能力分支、资料不进入系统规则、示例与真实解析器一致，以及三种协议实际发送的系统提示，其中仍保留历史附件数量分支的测试。`tests/test_streaming.py` 覆盖超过旧 1 MB 的持续流、摘要截断后的正文、协议包装、行/事件上限及跨片段凭据脱敏。`tests/test_review.py` 和旧网页附件行为测试仅覆盖保留的内部实现；这些测试通过不表示音频入口仍开放，入口退役边界需由 HTTP、会话和 MCP 测试分别检查。

这些测试使用模拟响应，只验证约定与实现；尚不能证明真实模型始终遵循提示或音乐效果改善。后续应由用户在熟悉的短选区，使用相同范围与播放设置在 SynthV 中试听确认；工作台不承担录音或听评。
