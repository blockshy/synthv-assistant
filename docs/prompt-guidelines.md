# 内置提示词规范

各模型任务共用 `synthv_assistant/prompts.py` 中的证据原则，再按本次能力和附件数量构造提示。提示词不包含密钥、工程路径、私有指纹或用户原文；当前要求、歌词和历史通过原有受限资料消息发送。增加新功能时，应同时核对实际解析器、工具契约和测试，避免只修改提示词而声称已经支持新动作。

## 任务与输出

| 功能 | 主要规则 | 输出 |
|---|---|---|
| 无选区咨询 | 回答当前问题，不虚构宿主读取或已执行操作 | 严格 `{text,actions}` JSON，`actions=[]` |
| 附带选区的调参 | 参考实际目录、现值与音符时间，默认保留已有音高；优先少量局部小幅修饰 | 最多五个不重复参数，按当前能力采用 `delta`、`curve`、`noteCurves` 或 `pitchShape` |
| 无音频请求 | 区分用户描述、乐谱、宿主计算音高与实际听感 | 不声称听过音频或取得录音基频 |
| 单段听评 | 只分析音频 A，围绕用户目标给可验证观察 | 中文文字及最多三项优先建议 |
| 双段听评 | 先检查可比性，A/B 只表示附件顺序，不预设 B 更好 | 同位置差异与取舍；无法比较时分别说明 |
| MCP 客户端 | 使用各工具公开字段，先读取、预览，再由用户确认应用 | 工具调用与简短说明；不套用聊天 JSON 或内部 `noteCurves` 字段 |
| 网页快捷提示 | 只填入具体需求，音频选择由显式动作标记触发 | 不自动发送、附加选区或上传历史音频 |

纯咨询不携带局部曲线和原生音高的完整动作说明；缺少可靠音符时间时不引导模型猜测 `noteCurves`。控制点模式不生成原生音高；原生重绘仅作为用户明确要求的替换操作，并说明不能保留全部演唱细节。声线名称始终以本次目录为准。

## 证据、篇幅与执行

要求模型简洁说明判断依据和不确定性，不重复全部规则、参数采样或内部推理。简单咨询通常不超过 200 字，调参说明通常 200～600 字，单项理由通常 20～80 字；听评通常 300～800 字。用户要求详细解释时可展开，但不得超出解析器硬限制：聊天 `text` 6,000 字符、单项 `reason` 1,000 字符、完整正文 24,000 字符。

音频时间应标为片段内约几秒。没有测量依据时不编造精确 F0、LUFS 或质量分数；静音、伴奏掩盖、内容不一致和响度差异应影响结论。现有采样不是完整曲线，宿主计算音高不是录音实测；缺失值不能补成零或默认值。

所有生成动作仍需本地结构、单位、能力与范围校验，并经过实际宿主预览和用户确认。提示词不能授予权限、解除边界或证明听感改善。模型响应遇到明确截断、过滤、工具调用或拒绝时不能作为完整方案；不自动重新调用付费接口。

公开思考摘要只展示供应商实际返回的内容，达到 12,000 字符后停止保留更多展示内容，继续接收最终答案。传输和最终正文采用独立预算，详见 [流式进度与限制](audio-review.md#会话模型选择进度与思考摘要)。

## 验证

`tests/test_prompts.py` 检查能力分支、附件数量、资料不进入系统规则、示例与真实解析器一致，以及三种协议实际发送的系统提示。`tests/test_review.py` 覆盖听评任务、结束状态和正文预算；`tests/test_streaming.py` 覆盖超过旧 1 MB 的持续流、摘要截断后的正文、协议包装、行/事件上限及跨片段凭据脱敏。前端行为测试检查快捷入口的显式附件选择。

这些测试使用模拟响应，只验证约定与实现；尚不能证明真实模型始终遵循提示或音乐效果改善。后续应由用户在熟悉的短选区，使用相同音频范围和播放设置试听确认。
