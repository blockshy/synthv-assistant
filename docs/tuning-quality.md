# 调教生成逻辑与参考记录

## 本轮调整的原因

旧实现把 `pitchShape` 作为绘制模式的优先音高方案：按乐谱 MIDI 重建整段音高，并给每个音符重复同一包络。这能约束旋律位置，却不能保留宿主原有的起音、过渡和颤音。另一个缺口是模型只看到参数范围、默认值和控制点数量，无法判断当前参数是否已经较强，容易持续同方向叠加。

现在将普通润色的规划默认改为保留已有音高、少量局部加法变化。原生重绘仍可用，但模型被要求仅在用户明确请求替换时采用，并在动作说明中显示覆盖生成音高的影响。这是规划策略，不是能证明模型完全理解自然语言意图的分类器；用户仍需确认实际预览。

## 模型判断与本地编译

1. 用户明确附带选区后，模型取得乐谱、真实起止秒数和可用参数目录。新桥接还提供 Automation 当前值的有限采样，每参数最多 33 点、选区合计最多 512 点。`minimum` / `maximum` 只是样本最值；采样不是完整原曲线、声线默认值叠加结果或最终声学测量。读不到就省略，不补零。
2. 本地生成 `musicalContext.noteLayout`，提供按时间排列的选区内序号、音符位置、实际时长、工程 MIDI 音高和前方间隔。150 ms 间隔只是分句参考，180 ms 只是提醒模型避免给短音符加复杂装饰；两者均非音频识别结果或普适唱法规则。
3. 模型可给不同音符提出不同的 `noteCurves` 包络。`note_curves.py` 使用宿主已换算的真实秒数编译为原有 0～1 曲线。模型不必自行估算全句坐标。音高微调用 `pitchDelta` 音分增量，声线模式仍须逐字匹配当前声库目录。
4. 每个局部包络的首尾为零增量，未指定音符及休止的**目标增量**为零。实际候选仍会经过原曲线插值、参数范围限制和宿主误差校验；不承诺这些区域逐位完全不变。多个音符包络最终合成同一参数动作，保持现有多参数组合预览。
5. 规划器编译后使用既有 `curve` 执行契约，同时由会话私有记录保存包络来源。复用逐音符通用参数时，要求音符数量相同，再按新片段的音符秒坐标重编译，避免“只改末音”在不同节奏下落到首音。音高曲线仍保留原有旋律与相对时值要求。旧版没有逐音符来源的通用曲线继续按整段时长缩放。

选区另可包含只读 `computedPitch`：使用官方接口按当前组引用读取最多 97 个计算音高样本，再将绝对 blick 坐标转换为实际秒比例。`ready` 表示本次读到结果，`pending` 表示宿主仍在计算，`unavailable` 表示接口不可用或读取无效；缺失帧保留为 `null`。采样不会阻塞等待合成，也不参与工程身份或应用指纹，防止异步计算进度导致旧提案频繁失效。它不是录音测得的基频，更不能从稀疏样本推断精确颤音频率或自动反算应写入的参数。

模型专用格式示例（只在规划响应中接受，HTTP/MCP 预览接口仍使用编译后的 `curve`）：

```json
{
  "parameter": "tension",
  "noteCurves": [
    {"noteIndex": 2, "curve": [[0, 0], [0.2, -0.05], [0.8, -0.03], [1, 0]]},
    {"noteIndex": 4, "curve": [[0, 0], [0.6, -0.04], [1, 0]]}
  ],
  "reason": "小幅放松第2与第4个选中音符，其余部分保留原目标值。"
}
```

`noteIndex` 是排序后的选区内 1-based 序号，不是工程音符 `index`。单项最多指定 32 个音符，每音符 3～8 点；最终仍最多 64 点。重叠音符、缺失秒数、重复目标、超限值或冲突字段明确拒绝，不能静默删掉音符、裁剪模型数值或放宽原有写入保护。

颤音包络只调节已有颤音的强度，不能把它当作具有指定频率的振荡器。原生 `pitchCurve` 与 `pitchDelta` 不得出现在同一模型计划中；规划阶段即提示冲突，避免到组合预览时才失败。

## 参考资料与独立实现边界

资料核对日期：2026-09-29。本轮仅阅读下列项目的公开说明及官方 API 文档，用来理解设计方法；未克隆、移植实现源码、复制提示词、预设参数表或素材，也未引入其依赖。许可证状态仅记录所读页面的标识，不代表本项目采用该项目代码。项目已有第三方依赖继续保留原许可与版权说明。

| 参考 | 观察到的设计 | 本项目的取舍 |
|---|---|---|
| [SVIXAGENT / AKDAgent](https://github.com/Akunda123/SVIXAGENT)（MIT） | 文档描述局部音高处理和宿主计算音高读取 | 参考保留非目标演唱、先获取实际状态的思路，独立实现有界读取及逐音符包络 |
| [SynthV Agent Bridge](https://github.com/SynthVCopilot/synthv-agent-bridge)（Apache-2.0） | 将音乐判断与确定性执行分离，提供工程及参数上下文 | 用自己的白名单格式和局部编译器落地；保留预览后人工确认 |
| [Turbo49 / SVScripts](https://github.com/Turbo49/SVScripts)（MIT） | 提供明确的手动音高及颤音控制 | 将“平直重绘”和“保留演唱后微调”视为不同意图，不把平直曲线作为自然唱法默认 |
| [dcuny / synth-v-scripts](https://github.com/dcuny/synth-v-scripts)（所读仓库主页未见许可证） | 说明中按音符、词和乐句位置处理表达 | 只参考局部定位与边界控制概念，不读取或复用其实现及默认数值 |

官方语义依据：

- [PitchControlCurve](https://resource.dreamtonics.com/scripting/PitchControlCurve.html)：原生曲线覆盖相应时间段的生成音高。
- [SV2 参数手册](https://sv2.docs.dreamtonics.com/en/parameters)：音高偏移叠加到生成音高，颤音包络调节已有颤音强度。
- [getComputedPitchForGroup](https://resource.dreamtonics.com/scripting/SV.html#getComputedPitchForGroup)：提供计算音高读取能力。读取值不能直接当作新的音高偏移或绝对曲线重新写入，否则可能重复加入已有控制。

## 验证与使用

离线测试使用合成音符、模拟模型响应和独立 Lua 宿主，覆盖实际秒坐标、短音、休止、组移调、逐音符不同幅度、非零原曲线、数值边界及资料过滤。它验证的是生成与应用逻辑，不是主观音质。

启用本轮上下文采样需更新安装桥接，并在 SynthV 重新运行；已有旧桥接仍可规划，但会缺少新增资料。重启本地工作台后重新发送需求才使用新规划策略，重新预览旧建议不会自动替换它的内容。

建议用同一短乐句做对比：保留原版录音 A，明确只修饰少量音符，检查组合预览后应用并录音 B，再按实际听感决定保留或撤销。没有模型真实响应与 A/B 试听证据时，不能宣称本次调整已经让某首歌更自然。
